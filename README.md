# Туман СПб

PWA с почасовой вероятностью тумана. Прогноз погоды берётся из [Open-Meteo](https://open-meteo.com),
вероятность считает модель, обученная на наблюдениях аэропорта Пулково. Ни ключей, ни бэкенда.

Живая версия: https://roadof7winds.github.io/fog/

## Запуск

```bash
npm install
npm run dev        # разработка (сервис-воркер отключён)
npm run build      # typecheck + сборка приложения + dist/sw.js
npm run preview    # прод-сборка на http://localhost:4173 (и в локальной сети: --host)
```

Чтобы поставить на телефон, нужен HTTPS: открыть ссылку выше и выбрать «Установить приложение»
(Android) или «Поделиться → На экран „Домой“» (iOS).

## Откуда берётся вероятность

Число на главном экране — не индекс и не эвристика, а вероятность, проверенная по наблюдениям.

**Данные для обучения** (`scripts/calibrate/`, в git не попадают, качаются заново):

- **Истина** — METAR аэропорта Пулково (ULLI) за 2015–2026 из архива
  [Iowa Environmental Mesonet](https://mesonet.agron.iastate.edu/request/download.phtml).
  Туман засчитывается по стандарту: видимость меньше 1 км либо код FG в сводке.
  Всего 102 649 часов, из них с туманом 1109 — это 1,07% времени.
- **Условия** — почасовой реанализ ERA5 в точке аэропорта из архива Open-Meteo.

**Модель** — логистическая регрессия на 20 признаках (дефицит точки росы, влажность, ветер и порывы,
общая и низкая облачность, осадки, приток радиации, температура почвы, тренды температуры и
насыщения за 3 часа, час суток и месяц) плюс изотоническая калибровка, чтобы предсказанные проценты
совпадали с наблюдаемой частотой.

```bash
node scripts/calibrate/fetch.mjs        # наблюдения + ERA5
node scripts/calibrate/fetch-extra.mjs  # дополнительные поля ERA5
node scripts/calibrate/fit.mjs          # обучение → src/lib/model.ts
node scripts/calibrate/evaluate.mjs     # метрики прежней эвристики, для сравнения
node scripts/calibrate/forecast-skill.mjs   # сколько точности теряет прогноз против факта
node scripts/calibrate/retro.mjs 2026-09-22 # сверка модели с фактом за конкретные сутки
```

Признаки описаны один раз в [`src/lib/features.ts`](src/lib/features.ts) и используются и обучением,
и приложением — иначе прогноз считался бы не по тому, на чём училась модель.

## Насколько это точно

Обучение на 2015–2022, проверка на 2023–2026 (эти годы модель не видела):

| | AUC | рабочая точка | поймано туманов | ложных тревог | CSI |
|---|---|---|---|---|---|
| прежняя эвристика (баллы) | 0.823 | балл ≥ 90 | 36,7% | 88,3% | 0.097 |
| текущая модель | **0.860** | p ≥ 8% | **46,7%** | **81,2%** | **0.155** |

Надёжность вероятностей на тех же проверочных годах:

| предсказано | часов | наблюдалось |
|---|---|---|
| 0–1% | 26 772 | 0,3% |
| 1–3% | 3 604 | 1,7% |
| 3–6% | 603 | 3,6% |
| 6–10% | 571 | 10,5% |
| 10–20% | 302 | 15,9% |
| 20–35% | 305 | 24,9% |

### Порог оповещения

Порог выбран не по математическому оптимуму, а по тому, как это ощущается. На проверочных годах
(44 тумана в год, считано по событиям, а не по часам):

| порог | уведомлений в год | оправдываются | поймано туманов | пропущено в год |
|---|---|---|---|---|
| 5% (выбран) | 137 | 16% | 61% | 17 |
| 8% (лучший CSI) | 91 | 19% | 51% | 22 |
| 12% | 52 | 25% | 35% | 29 |
| 20% | 20 | 32% | 15% | 38 |

Считает [`scripts/calibrate/alert-threshold.mjs`](scripts/calibrate/alert-threshold.mjs).

Уведомления приходят в два окна, потому что туман почти всегда ночью и под утро: вечером
(20:00–24:00) про ближайшую ночь и повтор утром в 7, если риск ещё впереди. Ночью приложение молчит.
Логика доставки проверяется тестом (`npm test`).

### Почему несколько моделей погоды, а не одна

1 октября 2026 в центре Петербурга была видимость около 200 м (видно по вебкамерам), а приложение
показывало 0,4–0,9%. Формула была ни при чём: модель погоды `best_match`, на которую приложение было
завязано, в этой точке тумана просто не увидела. Что говорили разные модели на 08:00–11:00:

| модель | Δ точки росы | видимость |
|---|---|---|
| best_match | 3,5–4,5° | 40–53 км |
| icon_eu | 0,0° | **40 м** |
| ukmo_seamless | 0,0° | **80–160 м** |
| meteofrance_seamless | 0,0–0,4° | — |
| ecmwf_ifs025 | 1,2–1,7° | — |
| gfs_seamless | 1,0–2,2° | — |

Четыре модели из шести туман видели. Поэтому приложение спрашивает все шесть и усредняет вероятность
(`scripts/calibrate/ensemble.mjs` сравнивает варианты на наблюдениях Пулково, 90 дней, 32 туманных часа):

| вариант | AUC | поймано | ложных |
|---|---|---|---|
| best_match | 0.983 | 91% | 76% |
| icon_eu | 0.983 | 100% | 79% |
| **среднее по моделям** | **0.984** | 97% | 76% |
| максимум | 0.973 | 97% | 89% |

Среднее не хуже лучшей одиночной модели там, где это можно измерить, и устойчивее там, где нельзя:
одна модель может ослепнуть, все шесть — вряд ли. На те же часы 1 октября среднее давало 16–20%.
Когда модели расходятся, приложение пишет об этом прямо на главном экране.

Низкой облачности и температуры почвы нет у части моделей, поэтому эти два признака не используются
ни для одной — иначе модели были бы несравнимы.

### Поправка на факт со станции

Ни одна модель погоды не знает, что туман уже идёт. А он очень «липкий» — по наблюдениям Пулково
за 2015–2026:

| сейчас на станции | туман через 1 ч | через 2 ч | через 3 ч | через 6 ч |
|---|---|---|---|---|
| туман | 57% | 40% | 30% | 12% |
| дымка (видимость < 4 км) | 6,6% | 6,5% | 5,7% | 4,7% |
| обычная погода | 0,3% | 0,5% | 0,6% | 0,9% |

При обычной частоте тумана 1,07%. Поэтому ближайшие 6 часов пересчитываются смесью «прогноз + факт»
(логистическая регрессия на логите прогноза и состоянии станции, обучение 2015–2022, проверка
2023–2026, `scripts/calibrate/nowcast.mjs`):

| заблаговременность | AUC без поправки | AUC с поправкой | CSI без / с | ложных тревог |
|---|---|---|---|---|
| +1 ч | 0.860 | **0.959** | 0.082 / **0.231** | 91% → 74% |
| +2 ч | 0.860 | 0.917 | 0.082 / 0.174 | 91% → 80% |
| +3 ч | 0.860 | 0.894 | 0.082 / 0.142 | 91% → 84% |
| +6 ч | 0.860 | 0.865 | 0.082 / 0.123 | 91% → 86% |

Поправка работает в обе стороны: туман на станции поднимает прогноз 2% до 49% на час вперёд, а
чистая станция опускает его до 0,1%. Применяется только если сводка свежая (не старше 2 часов) и
выбранная точка в пределах 60 км от Пулково; проверена она, разумеется, тоже только для станции.

### Сколько теряет прогноз

Метрики выше посчитаны на реанализе — то есть на погоде, которая уже случилась. В приложении на вход
идёт прогноз, и его собственная ошибка добавляется сверху. Замер на последних 90 днях (1835 часов,
42 с туманом), одни и те же часы, порог 8%:

| вариант | AUC | поймано туманов | ложных тревог |
|---|---|---|---|
| анализ (что было) | 0.969 | 67% | 56% |
| прогноз на сутки вперёд | 0.946 | 45% | 65% |
| прогноз на двое суток | 0.940 | 55% | 80% |

То есть на сутки вперёд модель ловит примерно вдвое меньше туманов, чем по факту погоды. Выборка
короткая и летняя, поэтому цифры ориентировочные; низкой облачности и температуры почвы в архиве
прошлых прогонов нет, поэтому эти два признака занулены во всех трёх вариантах.

### Сверка с реальным случаем

Туман 22 сентября 2026 (`node scripts/calibrate/retro.mjs 2026-09-22`): в Пулково он держался
с 01:00 до 10:00, видимость падала до 140 м. Что говорила модель:

| | вероятность на туманные часы |
|---|---|
| за двое суток | 11–25% |
| за сутки | 11–17% |
| по уже случившейся погоде | 12–30% |

При обычной частоте 1% это предупреждение в любом варианте.

## Чего эти цифры не значат

- **Туман плохо прогнозируется в принципе.** Верным оказывается примерно каждое пятое предупреждение.
  Для сравнения, в [работе Holtslag et al. (2010)](https://edepot.wur.nl/144635) классический
  Fog Stability Index дал CSI 0.38 на идеальной для тумана станции и медиану 0.23 по 12 станциям
  Нидерландов, а мезомасштабная модель MM5 — 0.22. Наш уровень примерно там же.
- **Это модель тумана в Пулково.** Аэропорт в 17 км южнее центра, на Пулковских высотах. Других
  станций с измерением видимости в радиусе 120 км от города нет, поэтому проверить прогноз для
  набережных или Кронштадта не на чем. У воды и в низинах туман бывает чаще.
- **Проверка велась на реанализе, а не на прогнозе.** Отдельный замер (см. выше) показал, что на
  сутки вперёд доля пойманных туманов падает с 67% до 45%, а ложных тревог становится больше.
- **Fog Stability Index не используется.** Он требует данных на высоте 850 гПа: в прогнозе Open-Meteo
  они есть, но в архиве ERA5 их нет, поэтому проверить FSI для Петербурга нечем. Добавлять
  непроверенную формулу к проверенной модели смысла нет.
- **Максимум модели — около 32%.** Это не осторожность, а частота: даже при идеальных условиях туман
  в Пулково возникает примерно в трети таких случаев.

## Как устроено приложение

- [`src/lib/predict.ts`](src/lib/predict.ts) — вероятность по каждой модели погоды и их среднее,
  калибровка, объяснение числа через вклад групп признаков.
- [`src/lib/api.ts`](src/lib/api.ts) — запрос к Open-Meteo сразу к шести моделям погоды
  (`wind_speed_unit=ms`, `past_days=1` для трендов и для показа уже прошедших часов).
- [`src/lib/observations.ts`](src/lib/observations.ts) — факт: сводки METAR Пулково прямо из браузера
  (сервер IEM отдаёт CORS). Определение тумана то же, что и в обучающих данных.
- [`src/lib/db.ts`](src/lib/db.ts) — IndexedDB: последний прогноз (офлайн), координаты, отметка об уведомлении.
- [`src/lib/notify.ts`](src/lib/notify.ts) — уведомления при вероятности ≥ 5%: вечернее и утреннее
  окна доставки, не больше одного уведомления на окно.
- [`src/sw/sw.ts`](src/sw/sw.ts) — сервис-воркер: офлайн-оболочка, кэш шрифтов, фоновая проверка.
- [`scripts/gen-icons.mjs`](scripts/gen-icons.mjs) — генерация иконок (`npm run icons`).

Деплой автоматический: push в `main` пересобирает и публикует сайт через GitHub Actions.

## Ограничения

- Без сервера нет настоящего push: уведомления приходят при открытии приложения, а на Android
  у установленного PWA ещё и через Periodic Background Sync (частоту определяет браузер).
- На iOS уведомления работают только у приложения, добавленного на экран «Домой» (iOS 16.4+).
- Это не официальный прогноз.
